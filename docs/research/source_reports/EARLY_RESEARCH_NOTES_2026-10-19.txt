# Punjab wheat and paddy supply anomaly prototype: public data research

**Research date: 19 October 2026.** Intended use is an expo demonstration and human-review signal only. A statistical anomaly is not proof of hoarding. Inventory machine-readable files include 32 candidate sources. Statuses are defined in the brief. “Verified” is used only where actual page data was inspected; documentation claims are not upgraded to successful API tests.

## Findings and source evidence

### Production, markets, procurement

Punjab OGD has a district/season/crop/year production resource described in hectares and tonnes, plus a food-grain area/production/yield catalog; its resource pages give crop examples extending 1968–2022. Treat exact crop-year coverage and units as resource-specific and record the download date. DES provides an official interactive district APY query for cross-checking. [Punjab district-season catalog](https://punjab.data.gov.in/catalog/district-wise-season-wise-crop-production-statistics-0), [Punjab food-grains catalog](https://punjab.data.gov.in/catalog/area-production-and-yield-food-grains-cultivation-punjab), [DES APY query](https://data.desagri.gov.in/website/apy-query-report-web).

AGMARKNET’s official SOP documents daily arrival and price entry, not an independently measured transaction ledger; its instruction that arrivals cannot be zero is a notable reporting constraint. The current backend is documented by the `makrand999` client, which lists filter, market, and daily report routes, but its README also states plain requests can receive 403 and its reference has a 404 probe example. The older `Prajwal-Shrimali` project is a local Flask wrapper around web scraping with a commodity/state/market route; it does not establish a historical arrivals API. CEDA says its market portal holds daily Ministry-sourced price and quantity-arrival data since 2001, but its API response was not tested. [AGMARKNET SOP](https://www.agmarknet.gov.in/DailyDataEntry/Docs/SOP_DEO.pdf), [current client README](https://github.com/makrand999/agmarknet-api), [reference](https://github.com/makrand999/agmarknet-api/blob/main/AGMARKNET_REFERENCE.md), [older scraper](https://github.com/Prajwal-Shrimali/agmarknetAPI), [CEDA portal](https://ceda.ashoka.edu.in/data-portal/), [CEDA API docs](https://api.ceda.ashoka.edu.in/documentation/).

CFPP publicly displayed Punjab wheat procurement with an estimate (124 LMT), day procurement (19,706.25 MT), progressive procurement (11,919,510.10 MT), and position date 15 May 2025 on the page captured. This is a state aggregate, not district data. CFPP menus list other weekly/district/centre and custom-milled-rice reports; those report titles are leads until actual rows, dates, columns, and downloads are inspected. Anaaj Kharid is an official operational portal but login/captcha and authorized-user workflows mean no public bulk dataset was verified. [CFPP report](https://cfpp.nic.in/cfppui/reports/reportsdata.html), [CFPP weekly reports](https://cfpp.nic.in/cfppui/reports/wpms_Weekly_reports.html), [CFPP CMR reports](https://cfpp.nic.in/cfppui/reports/milled_rice_reports.html), [Anaaj Kharid](https://anaajkharid.in/Home/).

### Weather, imagery, location and context

NASA POWER’s official daily API documentation specifies point/regional routes, JSON/CSV, daily UTC/LST time standards and 1981-to-near-real-time coverage. POWER is the simplest weather acquisition for a student. ERA5-Land offers hourly 0.1-degree historical reanalysis from 1950, with a CC-BY catalog; its ARCO guide warns that that implementation is experimental. CHIRPS offers 0.05-degree precipitation history from 1981; rainfall is a stress covariate, not a crop-loss observation. IMD’s cited 0.25-degree research rainfall dataset covers 1901–2010, but a current public download was not verified. [NASA POWER daily API](https://power.larc.nasa.gov/docs/services/api/temporal/daily/), [ERA5-Land catalog](https://cds.climate.copernicus.eu/datasets/reanalysis-era5-land-timeseries), [ERA5-Land guide](https://confluence.ecmwf.int/pages/viewpage.action?pageId=627854121), [CHIRPS ERDDAP](https://coastwatch.pfeg.noaa.gov/erddap/griddap/chirps20GlobalDailyP05.html), [IMD rainfall product paper](https://mausamjournal.imd.gov.in/index.php/MAUSAM/article/view/851).

Sentinel-2 imagery is free/open; Earth Engine catalog records 10/20m bands and 5-day nominal revisit, with catalog dates starting June 2015. Copernicus Data Space offers browser and API access subject to accounts/quotas. Neither is a ready-to-use wheat/paddy district statistics feed: cloud masking, crop calendar composites, labels and independent validation are needed. Bhuvan has a viewer and thematic layers, but this review did not verify a Punjab downloadable crop-statistics layer. [Earth Engine Sentinel-2 catalog](https://developers.google.com/earth-engine/datasets/catalog/COPERNICUS_S2_HARMONIZED), [Copernicus Data Space docs](https://documentation.dataspace.copernicus.eu/), [Bhuvan](https://bhuvan-app1.nrsc.gov.in/bhuvan2d/bhuvan/bhuvan2d.php).

DFPD annual reports and foodgrain bulletins provide central-pool stock, allocation/offtake and some storage/movement context. The 2024–25 annual report describes wheat/rice Central Pool stock, quarterly norms and a state stock annex; these are not a census of private or local stocks. Foodgrain bulletins include rail/road movement tables, but the public tables do not establish shipment-specific market routes. LGD monthly-updated district codes provide a join dimension; Punjab mandi coordinates/canonical keys need a separate verified market directory. [DFPD annual report 2024–25](https://dfpd.gov.in/WriteReadData/AnnualRecordUploadDocuments/b9c640b8-5889-4ffd-a62d-5b56c5d4f029_Food%20AR%202024-25%20English%20small%20size.pdf), [foodgrain bulletin archive](https://dfpd.gov.in/Home/FoodGrainArchiveList?language=1), [LGD districts](https://data.gov.in/resource/local-government-directory-lgd-districts).

Shipment-level e-way bill, toll, weighbridge and private warehouse records are not public prototype inputs. Public traffic/freight aggregates may contextualize volumes but cannot identify grain cargo, final destination, or actors. Do not infer an individual shipment from toll data. Census population and agricultural census holdings are background demand/farm-structure proxies, not local grain consumption or current crop volume.

## Priority shortlist

1. **Punjab OGD crop production series + DES APY query.** District/crop/season production and historical context are core expected-supply inputs. Obtain resource files and cross-check definitions/units before comparing vintages.
2. **AGMARKNET 2.0 with CEDA as an alternate.** These are the strongest candidate market-arrival/price sources. First deliverable should be a 2–3 market, 30-day response validation. Require real dates, quantity units, commodity identity, and stable market key; do not start the model until this passes.
3. **CFPP public procurement reports.** Easy-to-view state aggregate and report families can contextualize official procurement. Use only verified level and dates; manually export or ask FCI for historical report extracts if needed.
4. **NASA POWER daily weather.** Free, reproducible low-friction covariates; daily precipitation/temperature aggregates can inform weather-adjusted expectations.
5. **Sentinel-2 via Earth Engine or Copernicus.** Independent area/condition evidence, but advanced and not required for the first credible baseline.

DFPD stocks/bulletins, LGD district codes and Census demand proxies round out contextual inputs. For the first demo, prioritize 1–4 and one district/season; don’t wait for remote sensing.

### Cleaning and fallback

Maintain raw and canonical values. Normalize crop aliases to `wheat`, `paddy_unhusked`, and `rice_milled` only where source semantics support it; never equate paddy arrival with milled rice. Preserve arrival units as source-provided, then convert quintals/tonnes only with documented source units (1 quintal = 0.1 metric tonne; 1 kg = 0.001 tonne). Normalize dates to ISO `date`, retain source timezone, crop year and season separately. Resolve district/market names via versioned lookup tables; do not fuzzy-join without review. Treat blank, suppressed, zero and “not reported” as different states. Keep revisions and duplicate records, deduplicate only by source-native key after assessing updates. Fallbacks: production OGD ↔ DES/Statistical Abstract; market AGMARKNET ↔ CEDA ↔ manual official export; weather NASA POWER ↔ CHIRPS/ERA5-Land; procurement CFPP ↔ DFPD reports; imagery Sentinel ↔ Landsat.

## PostgreSQL model and joins

Use dimensions `dim_crop(crop_id, canonical_name, source_name, commodity_code, form, unit_basis)`, `dim_district(lgd_code, name, valid_from, valid_to, geometry_id)`, `dim_market(source_market_id, canonical_market_id, district_id, name, lat, lon, valid_from, valid_to)`, and `dim_season(crop_year, season, start_date, end_date, harvest_window_start, harvest_window_end)`. Facts: `fact_production(district_id,crop_id,season_id,area_ha,production_t, yield_kg_ha,estimate_stage,source_id,source_row_id,observed_at)`, `fact_mandi_daily(market_id,crop_id,date,arrival_qty,arrival_unit,min_price,max_price,modal_price,source_id,source_row_id,reported_at)`, `fact_procurement(location_id,commodity_form,date_or_period,qty_t,agency,season_id,source_id,grain_type)`, `fact_weather(location_or_grid,date,variable,value,unit,source_id)`, `fact_satellite_summary(geometry_id,crop_year,window,ndvi_median,classified_area_ha,model_version,confidence,source_id)`, and `fact_estimate(district,crop,season,expected_qty_t,interval_low_t,interval_high_t,model_version)`. `source_registry` records URL, access date, license, retrieval parameters, checksum, evidence status and notes.

Join annual production to district + crop + season/crop-year; join arrivals by canonical market + crop + date, then map market to district with a versioned crosswalk. Join procurement only at its stated geographic/time resolution. Aggregate each fact separately before joining; never join daily arrivals directly to several procurement rows or multiply quantities through many-to-many locations. Keep `arrival_qty`, `procurement_qty`, `traded_qty` separate. Do not add procurement to mandi arrivals unless source documentation proves disjoint channels; procurement may be included in arrivals already. Distinguish paddy (unmilled) from rice (milled) and preserve conversion/recovery assumptions separately. Missing values remain NULL with a reason code; zero means a recorded zero only when source allows it. Keep observed facts, model-derived estimates and synthetic demo rows in separate schemas or tables with `record_class` and a prominent UI badge.

## Anomaly feasibility and interpretation

- **Production anomaly:** feasible as an annual estimate deviation after consistent area/yield vintages and uncertainty. District estimates and current-season official estimates may be delayed or revised.
- **Mandi-arrival anomaly:** feasible at mandi/day if actual arrivals are verified. Use a seasonal calendar and same-mandi/same-week-of-season historical baseline, robust median/MAD or negative-binomial count/volume model, holidays, harvest timing, reporting coverage, weather and lag. Show missing-report flags separately.
- **Price anomaly:** feasible with daily modal price if the same grade/variety/market is aligned. A sharp move may reflect demand/quality/transport and is not evidence of withholding.
- **Procurement discrepancy:** partially feasible where CFPP has comparable procurement totals, dates and geography. Account for private sale, procurement eligibility, quality rejection, procurement center operation and delayed reporting.
- **Transport-flow anomaly:** not feasible as shipment attribution from public data. Only macro movement context is available.
- **Possible withholding/hoarding:** not established by public data in this prototype. Low arrivals can result from harvest timing, local consumption, direct mill/contract sales, storage, transport disruption, weather loss, mandi reporting omissions, alternate markets or procurement timing. Require independent production/area estimates, verified arrivals from all relevant markets, price/market-spread evidence, procurement/stock/milling reconciliations and authorized shipment/storage records before human escalation. A dashboard label should say “unusual supply signal—review required,” never accuse a named trader or farmer.

For every alert, expose expected range, observed source and coverage fraction, data freshness, season/week, weather covariates, procurement context, competing explanations, uncertainty and exact provenance. Back-test only on events whose labels are independently documented; news reports alone are not ground truth.

## Statistical model comparison and recommendation

| Task/method | Data requirements and practical fit | Strengths | Risks/cost |
|---|---|---|---|
| Annual production: historical median / linear trend by district-crop | Ideally 10+ consistent years per district/crop; official area/yield definitions harmonized | Transparent and robust first benchmark; easily show baseline vs current official estimate | Structural changes, boundary changes and revised estimates; annual series may be too short or discontinuous |
| Production: area × yield regression with weather/remote-sensing covariates | Matched district-year data, crop area, weather; satellite labels for classifier | Decomposes area and yield; can represent weather shock | Sparse annual sample, non-stationarity, remote sensing requires field truth; risk of false precision |
| Arrivals: seasonal-naive same crop-week/day previous year(s) | Daily market arrivals across seasons; market/crop and date/calendar | Strong low-cost benchmark; intuitive; captures season | Calendar shifts and reporting gaps; prior year shock can poison baseline |
| Arrivals: same-week robust median + MAD, weekday/harvest calendar strata | Multiple years daily arrivals with complete/missing flags; ideally 3-5 seasons minimum | Interpretable, resistant to outliers, easy to explain | At least 3 years; sparse markets and missing reports make intervals unstable; MAD=0 edge case needs fallback scale |
| Arrivals: SARIMA/ETS with exogenous covariates | Prefer multiple years daily/weekly series; event calendar, price/weather/procurement features | Forecast intervals and autocorrelation modeling | Parameters brittle with short, interrupted or strongly seasonal series; tuning and diagnostics needed |
| Multivariate ML (Isolation Forest, gradient boosted residuals) | Many validated markets/features, quality missingness, several seasons | Can capture interactions and rank contributors | Unsupervised Isolation Forest scores lack causal interpretation; high false-alert risk and opaque calibration; not suitable as first detector |
| Price: seasonal baseline / forecast residual | Daily same market, grade, variety, price definition | Available alongside arrivals; useful context | Price not quantity; quality mix and grade changes confound |

**Recommended primary detector:** per market × commodity, align date to crop-season phase and weekday, build historical seasonal expectation as the median of comparable prior-season observations, estimate a robust residual scale from MAD (fallback to IQR or pooled market/season scale when MAD is zero), and flag observations outside calibrated empirical prediction bounds. Include data completeness and freshness in the alert score. For annual production, use a district/crop robust trend or rolling median of area × yield, with a prediction interval and official forecast shown as separate reference. **Benchmark:** prior-year same-season day/week plus a simple district annual median. Require 3 complete prior seasons before market-level statistical flags; with less history, show descriptive comparisons only. Evaluate forecast residuals on walk-forward time splits before alerting.

Forecasting accuracy does not imply anomaly or cause accuracy. A peer-reviewed agricultural sales study reports gains from external calendar/weather features but uses well-resourced business data; it is motivation to test covariates, not evidence that it improves Punjab arrivals. [Study](https://doi.org/10.1016/j.eswa.2024.123438). Uncertainty intervals should be checked for actual coverage rather than treated as automatic confidence. [Agricultural forecast uncertainty study](https://doi.org/10.1002/ajae.12075). The recommendation above is a project design inference from the available series and constraints, not a claim of locally validated predictive performance.

## Adversarial debate and decision

| Debate point | Advocate | Sceptic / contrary evidence | Missing evidence and cost of error | Reviewer decision |
|---|---|---|---|---|
| Production-to-arrival discrepancy could reveal withheld grain | Punjab production and daily mandi reports could indicate unusual marketed supply | Production is annual/estimated, arrivals cover reporting mandis, and crop can be stored, self-consumed, sold privately, milled directly or move to other markets; procurement may overlap arrivals | Need farm-gate/alternate channel sales, private stocks, inter-state flows and inventory change; false attribution risks accusing legitimate actors | Keep as “observed supply anomaly,” never as hoarding inference |
| Satellite can independently validate expected crop | Sentinel imagery can estimate area and crop phenology independently of official aggregates | No ready Punjab wheat/paddy area layer verified; classification requires field labels and ground truth, mixed pixels and cloud issues | Need labeled fields/crop cut validation; wrong classification biases baseline | Future version; imagery corroborates area/condition but does not replace official estimates |
| Low arrivals signal concealed inventory | Persistent low arrivals plus high production and strong prices is suspicious enough to investigate | Prices can rise under demand, quality shifts, procurement delays, exports, logistics or neighboring-state effects; arrivals have reporting gaps and mandatory nonzero entry in SOP | Need stock inspection, verified location-specific inventory, shipment flows and causal comparison | Do not make actor-level claims; build context panel and escalation checklist only |
| Public procurement is a usable reconciliation ledger | CFPP exposes state quantities and lists finer procurement/CMR reports | Verified page shows state wheat aggregate; Punjab operational portal requires login; report menus do not prove accessible rows | Need machine-readable historical daily district/centre records and definitions of procurement vs arrivals | State-level season context only until detailed reports are pulled and schema audited |
| Complex anomaly ML improves expo value | Isolation Forest or deep models produce a visually attractive score | No trustworthy labels, short histories and irregular reporting make scores difficult to calibrate or explain | Unjustified false positives damage credibility | Start robust seasonal forecast residual + interval, retain model score as exploratory only after backtest |

**Go/no-go:** **Go** for an explainable, non-accusatory agricultural supply anomaly monitor using production baselines, weather, verified mandi reports and procurement context. **No-go** for a system that claims to detect hoarding or identify responsible actors with present public data. This boundary changes only if independent stock, shipment, processing and alternative-market observations become legally available and a causal validation design supports the specific claim.

## Architecture, data flow and operating plan

`source registry → raw immutable files → schema/quality checks → normalized PostgreSQL facts → seasonal feature views → walk-forward baseline/intervals → explainable alert table → local dashboard/map`.

- **Ingestion:** Python `requests` clients for tested public APIs, manual downloads for OGD/CFPP PDFs until a public machine-readable interface is confirmed. Store the raw bytes, request URL/parameters, retrieval time, HTTP status, checksum and source label. Make each import idempotent and retain source revisions.
- **Processing:** pandas for tabular validation and normalization; GeoPandas/PostGIS only after trustworthy district boundaries/market coordinates are obtained. Rasterio/xarray for remote sensing/weather rasters if the team actually implements satellite features.
- **Database:** PostgreSQL; PostGIS optional. Use dimensions and fact tables from `schema.sql`, unique source keys where confirmed, constraints for units and `record_class`; do not flatten all source tables into one spreadsheet.
- **Modeling:** Python/scikit-learn or statsmodels only where justified. Establish descriptive seasonal reference first; store forecasts, bounds, model version and input source IDs in separate estimate/alert tables.
- **Service/UI:** FastAPI only if separate frontend or API consumers are needed. For fastest local expo, Streamlit or a static Plotly Dash screen can query precomputed PostgreSQL views; Folium/Plotly map only after boundary sources are validated. Run everything locally with Docker Compose or native PostgreSQL; no paid cloud dependency.
- **Reproducibility:** pinned Python dependencies, config file for source endpoints, `.env` for secrets, `make ingest/check/model/dashboard` or documented commands, dated raw files, and a small public-data fixture for offline demo. Synthetic fixtures use `data/synthetic/` and cannot share a chart without a visible synthetic badge.

**Data quality gates:** schema drift, invalid date/unit, duplicate source key, impossible negative quantity, stale update, missing market-day density, unknown crop/market alias and coverage gaps. A “zero” is not imputed for unreported values. API success means valid status plus expected JSON fields and a nonempty plausible sample—not merely HTTP 200.

## Validation plan

1. Freeze the source snapshot and document revision dates before constructing features. Split by time, never randomly. Walk forward by crop year/season, keeping the last full season as a final holdout where sample length permits.
2. Forecast accuracy: report MAE and RMSE in tonnes (with market-size stratification); use seasonal MASE only when the seasonal-naive denominator is valid. Compare with seasonal-naive. For price report MAE in source currency/unit.
3. Interval quality: empirical 80/90/95% coverage, interval width and calibration by market/crop/season. If actual coverage is below nominal, widen/recalibrate or suppress alert confidence.
4. Alert quality without hoarding labels: count alert days per market/season; inspect sampled normal and extreme periods with an agronomist or documented records; compare alerts against known reporting gaps, procurement starts, holidays and documented weather/disaster periods. Report candidate-alert review rate, not precision/recall for hoarding.
5. Missingness sensitivity: rerun after dropping markets/days, simulate missing reporting blocks (synthetic only), and compare alert movement. Separate true zeros from missing records. Test district aggregation with and without markets lacking stable location mapping.
6. Synthetic anomaly injection: inject controlled dips/spikes, delayed season peaks and missing blocks into a copy of observed series, label the altered copy synthetic, and verify the pipeline detects injected deviations. This tests code behavior only, not real-world sensitivity or crime detection.
7. Leakage audit: weather availability timestamp, crop estimates publication date, procurement report revisions, and future arrivals must be unavailable to historical forecast features if they would not have been known at prediction time.
