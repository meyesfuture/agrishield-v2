## Results

The final reproducible run tested 15 URLs. Six returned HTTP 200; three valid payloads were saved: a complete Survey of India map PDF (24,579,664 bytes), a NASA POWER daily weather JSON response (774 bytes), and an unfiltered Copernicus catalogue JSON response (3,911 bytes). Three other HTTP 200 responses were HTML catalog/portal/release pages and were logged as endpoint-only. Nine probes did not receive HTTP 200, mostly due to Python TLS validation errors; the FCI dashboard timed out. No Punjab crop production, mandi observation, procurement record, stocks or movement series, historical weather series, satellite pixels, district GIS vector, or verified hoarding event records were acquired.

Nine probes did not return HTTP 200 in the final run: several endpoints rejected Python's TLS validation with expired, self-signed, or untrusted certificate-chain errors; the FCI dashboard timed out. These are client transport failures, not proof that sources are down. The initial legacy-TLS test was a Pakistan Punjab page and is excluded from the India source register; the corrected test used the official Tarn Taran district portal and returned HTML only. The exact results and hashes are in [`logs/acquisition_log__20261020T172122Z.csv`](logs/acquisition_log__20261020T172122Z.csv), [`logs/acquisition_log__20261020T172746Z.csv`](logs/acquisition_log__20261020T172746Z.csv), [`logs/acquisition_log__20261020T173044Z.csv`](logs/acquisition_log__20261020T173044Z.csv), and [`logs/acquisition_log__20261020T173446Z.csv`](logs/acquisition_log__20261020T173446Z.csv); corresponding run summaries are saved beside them.

- `raw/nasa_power_ludhiana_week__20261020T173446Z.json`: valid NASA POWER response for all seven dates requested (2025-01-01 through 2025-01-07), both variables present with non-null values across the seven days. `T2M` is in °C and `PRECTOTCORR` in mm/day; header specifies UTC and MERRA2 source. The acquisition log records schema, dates, units, and UTC validation. This is a successful small historical weather sample, not evidence of long-range historical completeness.
- `raw/sentinel_copernicus_catalog__20261020T173446Z.json`: 3,911-byte successful OData response. The first unfiltered item is Sentinel-3 SLSTR at a non-Punjab footprint; this is catalogue metadata only, not imagery and not a Punjab match. Earlier duplicate metadata responses are also preserved.
- The crop-production catalog and Punjab Mandi Board each returned HTML only. The crop catalog describes district/crop/season/year area in hectares and production in tonnes, but no rows were included in the downloaded page. Its API link leads to a key-generation page; actual API access remains untested.

## Priority source findings

- **Production:** The OGD/DES [district-wise, season-wise crop production catalog](https://punjab.data.gov.in/catalog/district-wise-season-wise-crop-production-statistics-0) is a promising primary source; metadata says area and production are available, but API/ZIP acquisition, years, completeness, and wheat/paddy codes remain unverified.
- **Mandi:** eNAM's [Agmarknet dashboard](https://www.enam.gov.in/web/dashboard/agmarknet) exposes market, commodity, arrival, price range, and date fields in its indexed interface. The request failed TLS validation, and no downloadable daily observations were obtained. Punjab's [Mandi Board portal](https://emandikaran-pb.in/) loaded as HTML, not records.
- **Procurement/stocks/movement:** [CFPP/WPMS](https://cfpp.nic.in/cfppui/reports/wpms_days_reports.html) publishes procurement report navigation but failed TLS validation. FCI's [IISFM dashboard](https://iisfm.nic.in/fcidashboard/FCIRegionDashboard.aspx?code=NF) timed out. Indexed FCI/DFPD records show relevant state totals and stock statements, but those are not local acquisitions in this run. Do not trust dashboard zeros without validating the report's refresh/as-of date.
- **Weather:** The initial sibling diagnostic had no DNS resolution to NASA POWER. The repeated exact [NASA POWER Daily Point request](https://power.larc.nasa.gov/docs/services/api/temporal/daily/) succeeded here for seven dates and two parameters. Script-level validation confirms date keys, requested parameter set, non-null rows, units, and UTC. It demonstrates endpoint/data access for this bounded sample only. IMD endpoints still failed Python TLS validation.
- **Satellite:** Copernicus metadata access works, but the probe was intentionally a one-item, unfiltered catalogue check. The returned record is Sentinel-3 at a non-Punjab footprint. No Punjab AOI/date selection, Sentinel-2/Sentinel-1 scene retrieval, cloud mask, pixels, or imagery processing was tested. Image download access may require account/token setup.
- **Boundaries:** A complete [Survey of India 2025 Punjab map](https://surveyofindia.gov.in/UserFiles/files/PUNJAB_STATE_MAP_ENGLISH_2025.pdf) was acquired; it describes administrative boundaries updated through 2024. It is not a GIS vector. The [Punjab State GIS portal](https://www.stategisportal.nic.in/stategisportal/Home/Map/3) could not be retrieved by Python TLS.
- **Historical mandi API:** The prior diagnostic documented CEDA's official Agmarknet Swagger routes but did not verify server base URL or POST schemas. Its earlier DNS failure is now a TLS certificate validation error for the documentation URL. No data route was queried; do not infer request paths or bodies.
- **Ground truth:** No incident dataset was downloaded. A search surfaced an official Tarn Taran district release about missing Pungrain godown stock and an FIR; that is a promising **public-stock discrepancy** lead, not a private-hoarding confirmed label. A separate Pakistan Punjab police page must not be used for Punjab, India. Sources need incident-level jurisdiction and legal-status checks.

## Reproduce

Run `python scripts\acquire.py` with Python 3.10+ and a trusted network/TLS environment. The script uses 15-second per-source limits and caps response reads at 100 MB; PDF payloads are saved only when a PDF EOF marker is present. It will append timestamped files/logs instead of overwriting current evidence. The current TLS and incomplete-response failures should be retried through the OS trust store or official browser/API route, without disabling certificate verification.
